### Исправлено
- GPU-слои больше не фиксируются в 99 для новых профилей: значение -1 включает штатный fit с резервом памяти и автоматическим распределением, не передавая сохранённый ручной tensor-split; ручные значения и контекст сохраняются
- Профили нагрузки сохраняют выбранные KV-cache K/V и Flash Attention: применение профиля больше не включает q8_0 принудительно; для Flint проверен f16/f16 на длинном распределённом запросе
- Недоступный RPC отклоняется до загрузки модели: адрес в строке ошибки подключения больше не считается подтверждённым устройством
- Проверка готовности ждёт запуска backend при временном HTTP 502 inference-шлюза вместо немедленной остановки модели; сохранены таймаут, отмена и обнаружение завершения процесса
- Максимальный профиль задаёт 131072 (128K) токена контекста; при лимите ответа 32768 для входа остаётся 98304 токена, подсказки и документация согласованы с профилем
- Воспроизведены и устранены потеря ключей при закрытии, пропуск null ModelSettings, применение снимка прежнего адреса к новому узлу и отображение неизвестной занятой VRAM как нулевой
- Настоящим TLS-тестом воспроизведён отказ Windows SChannel при EphemeralKeySet; сервер использует пользовательский контейнер ключа с освобождением при Dispose
- Регрессионными тестами воспроизведены и устранены обрезка подписи верхнего переключателя роли и потеря отмены при чтении поддержки Effort
- Воспроизведённые тестами ошибки проверки полного build и повторно используемой установки, порядка --rpc перед --list-devices и обработки HTTP-ошибки без API-ключа
- Результаты автопоиска обновляют язык вместе с UI; пустой старый settings.json LM Studio не вызывает ложное предупреждение чтения
- Восстановление агента распознаёт устаревший Microsoft.NETCore.App; кнопка скачивает и проверяет оба установщика, затем устанавливает обычный .NET Runtime и ASP.NET Core Runtime одной версии вместо установки только ASP.NET
- Сообщение отсутствующего runtime не теряется при быстром завершении apphost и не выводится в UI необработанным англоязычным текстом
- Относительный путь публикации Desktop после переноса исходников в Sources направляет сборки в Releases внутри каталога проекта
- Найденные автономными тестами ошибки предпросмотра и выбранных локализованных значений устранены
