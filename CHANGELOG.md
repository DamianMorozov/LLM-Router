# Журнал изменений

[0.2.200]
### Добавлено
- Основа кроссплатформенного приложения на Avalonia Desktop и MVVM для настройки одной локальной LLM на нескольких компьютерах; назначение и состав проектов описаны в [концепции](CONCEPT.md) и [архитектуре](ARCHITECTURE.md)
- Роли главного компьютера и сетевого узла, профиль подключения, выбор GGUF и предпросмотр команды llama.cpp с проверкой параметров
- Русский и английский интерфейсы, светлая и тёмная темы
- Автоматическое сохранение и восстановление профиля, языка, темы, положения и размеров окна; общий переключатель запоминания настроек
- Проверки штатного и отменённого закрытия, отключённого сохранения, повторного включения и восстановления окна на доступном мониторе
- Термин OpenAI-compatible client для внешнего приложения, подключаемого к API модели
- Иконка Desktop в SVG/PNG/ICO, многоразмерный ресурс Windows EXE и команда пересоздания ресурсов
- Папка Docs с основными документами и лицензией в решении
- Публикация Agent вместе с Desktop в подкаталог Agent с теми же RID и режимом self-contained; отдельные каталоги публикации для выбранной платформы
- Вкладка агента текущего ПК: адрес, порт, LAN, генерация, показ и копирование ключа, запуск с проверкой MagicOnion и остановка при закрытии окна
- Локальные и удалённые TCP-проверки портов агента и вычислительного RPC
- Создание и обновление собственного правила Windows Firewall через UAC для порта агента с ограничением Private / LocalSubnet
- Проверки дочернего агента, авторизации, очистки процессов и PowerShell-правила с подменой системных команд
- Восстановление отсутствующего или устаревшего .NET и ASP.NET Core Runtime: понятное сообщение apphost и кнопка установки согласованной пары для архитектуры агента
- Загрузка стабильного runtime 10.0.x с Microsoft, проверка SHA-512, прогресс, UAC, обработка отмены, ошибок и требования перезагрузки
- Автопоиск llama.cpp в известных каталогах, PATH и backends LM Studio, список результатов и отдельные признаки server/RPC
- Поиск каталога моделей по downloadsFolder LM Studio, ручной выбор, сохранение каталога и начальная папка диалога GGUF
- Копирование и очистка журнала с маскированием известных ключей; команды не меняют состояние работающих процессов
- Проверки поиска на изолированных каталогах, XAML-команд, буфера обмена, локализации результатов и совместимости профиля
- Локальная установка закреплённой сборки llama.cpp на каждом ПК: основной CUDA-пакет и cudart одного релиза, SHA-256 GitHub, проверка CLI/RPC и точного build, отдельные каталоги версий и повторное использование установок
- Запуск и остановка RPC или llama-server по роли, отмена, таймаут, ограниченный журнал процесса и отдельное правило RPC Windows Firewall
- Проверка одинакового build агентов и настоящих RPC-устройств перед запуском кластера, ожидание /health и авторизованного /v1/models, контрольный запрос /v1/chat/completions
- Параметры build, backend, GPU-слоёв и таймаута в профиле; передача ключа inference API дочернему процессу через окружение и кнопка копирования ключа
- Тестовый дочерний EngineFixture, нативная проверка CPU/RPC с маленьким GGUF через окно Avalonia и проверка официальных CUDA-пакетов без системной установки
- Дополнительные параметры модели: Max Output, sampling, Reasoning, бюджет рассуждений, параллельные запросы, batch/microbatch, Flash Attention и KV-cache K/V с сохранением и передачей в CLI
- Карточки нагрузки всех компьютеров на «Обзоре»: CPU, отдельные NVIDIA GPU/VRAM, время снимка, состояния связи, ручной и автоматический опрос
- Системные счётчики CPU Windows/Linux и top macOS, телеметрия GPU через nvidia-smi, совместимые MessagePack DTO и скрытие устаревших показателей
- TLS агента с постоянной защищённой идентичностью, закрепление SHA-256 сертификата, проверка сопряжения и отдельное разрешение управления собственным RPC через INodeControl
- Защищённое хранение ключей агентов отдельно от JSON-профиля: DPAPI Windows или AES-GCM с приватными Unix-файлами, общий и отдельный переключатели сохранения
- Проверка build и устройств CUDA/RPC, подбор пропорций по свободной памяти с резервом, настройка --device и --tensor-split, два контрольных запроса с раздельными prompt/generation timing, скоростью и кэшем
- Вариант языка «Как в системе» / System language, определение по CurrentUICulture с английским fallback и повторный выбор языка при запуске; проверки ru-RU/en-US/de-DE
- Верхний переключатель роли, компактные карточки «Обзор» и «Агент», согласованная высота элементов, подписи рядом с переключателями и компактные кнопки копирования и очистки журналов
- Этапы и прогресс загрузки модели, корректная остановка движка при закрытии окна, выбор интервала автообновления и сохранение значения в профиле
- Название Open LLM Cluster в окне и метаданных, знак OLC, имя репозитория Open-LLM-Cluster и скриншоты интерфейса в тёмной теме на русском языке
- Профили нагрузки, показ системной RAM рядом с CPU, Model ID с кнопкой копирования и краткое состояние текущей работы модели
- Версия с префиксом v в заголовке окна, блокировка настроек по роли и карточка «Готовность» с индикаторами и командами запуска и остановки движка и агента
- Сохранение ключа inference API между сеансами вместе с ключами агентов в защищённом хранилище согласно переключателям запоминания
- Максимальный профиль с контекстом 131072 (128K) и лимитом выхода 32768 (32K) токенов; при полном ответе для входа остаётся 98304 токена
- Справка по Effort загруженного шаблона с копированием доступных уровней; передача значения из запроса клиента, fallback к настройке по умолчанию и сообщение рядом с Model ID
- Сравнение с LM Studio / LM Link и NVIDIA PAIR, схема подключения клиента к inference-шлюзу OLC, объяснение RPC и таблица сетевых портов в [подробном руководстве](READEME-DEV.md#rpc-и-порты)
- Ожидание готовности backend при временном HTTP 502 шлюза, обнаружение раннего завершения процесса и сохранение исходной причины ошибки с маскированием ключа
- Сохранение выбранных KV-cache K/V и Flash Attention при применении профиля нагрузки; нативная проверка Flint с f16/f16 на длинном распределённом запросе
- Локальная копия GGUF на сетевом узле: выбор пути, сверка размеров и SHA-256 всех частей с главным ПК, подготовка штатного кэша RPC с диска, повторное использование кэша и отмена
- Автоматический подбор GPU-слоёв: -1 включает штатный fit с резервом памяти и автоматическим распределением без ручного tensor-split; доступны также CPU и фиксированное число слоёв
- Автономные проверки TLS, сопряжения, секретов, устройств, профилей, процессов, API, локального кэша и интерфейса; результаты нативных проверок и границы приёмки описаны в [документе тестирования](TEST-Project.md)
- Краткий [README](README.md) для первого запуска и [подробное руководство](READEME-DEV.md) с настройками, сборкой и разработкой; навигация между документами и ссылки в решении
